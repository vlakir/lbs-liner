## Цель

Схема приходит в виде CDR-файла CorelDRAW, где граница зоны нарисована
«заливкой» — многоугольник, залитый цветом и замкнутый искусственными
прямыми рёбрами. Для дальнейшей работы нужна не заливка, а классическая
**двойная контурная линия**: красная — с внутренней стороны (где была
заливка), синяя — с внешней. Утилита делает это преобразование
автоматически, вместо многочасовой ручной обводки в Corel.

## Пользователь

Разработчик и заказчик: обмен файлами в формате CorelDRAW. Запуск — из
командной строки на Windows или Linux, без установленного Python
(собранный исполняемый файл).

## Ключевая функциональность

- Читает CDR (zip-формат CorelDRAW X7+, версии 17–22) без внешних
  программ и библиотек-конвертеров.
- Находит контуры залитой области: основную ломаную границы (отбрасывая
  искусственные замыкающие рёбра и заливку), карманы-островки вдоль неё
  и отдельные мелкие замкнутые контуры.
- Строит две параллельные линии на заданном расстоянии: красную со
  стороны заливки, синюю с противоположной. Сторона определяется
  геометрически, по положению залитой области.
- Толщина линий и расстояние между ними — параметры CLI с дефолтами
  (0.2 мм / 0.6 мм).
- Пишет результат в CDR, открываемый тем же CorelDRAW; размер и
  пропорции геометрии сохраняются точно.

## Out of scope

- Универсальный конвертер/редактор CDR — не делаем. Читаем и пишем
  ровно то подмножество формата, которое нужно задаче.
- Старые (не-zip, до X7) версии CDR — не поддерживаем.
- Генерация CDR «с нуля» — не делаем: выход собирается патчем входного
  файла (это гарантирует совместимость с версией Corel отправителя).
- GUI, предпросмотр, интерактив — не делаем: только CLI.
- Прочее содержимое документа (текст, растры, другие слои) — не
  трогаем; утилита работает только с геометрией залитой области.

## Ограничения и догадки

- Python 3.14+, `uv`; единственная тяжёлая зависимость — `shapely`
  (построение смещённых линий); упаковка PyInstaller под Windows и
  Linux.
- Формат чанков CDR восстановлен по исходникам libcdr и проверен на
  реальном файле; предполагаем, что входные файлы будут того же
  семейства версий (17–22). Файл другой структуры утилита должна
  отвергать с внятной диагностикой, а не портить.
- Проверка результата в настоящем CorelDRAW ни одной из сторон
  разработки недоступна — остаётся ручным шагом приёмки у заказчика;
  локально результат сверяется рендером через libcdr (Inkscape) — это
  dev-инструмент, в рантайм утилиты не входит.
- Исходные файлы пользователей — чувствительные данные: в репозиторий
  и тесты не попадают, всё тестируется на синтетической геометрии.
