# Роли команды: Архитектор и Дизайнер

Проект укомплектован переиспользуемым контуром сотрудничества поверх
методики. Оркеструет **лид** (эта сессия Claude Code), финальные
решения принимает **человек** (Разработчик). Две роли доступны по
умолчанию — пользоваться ими в конкретной задаче или нет, решает лид
по ситуации, а не галочка при создании проекта.

Источник истины и «память» ролей — штатные файлы методики проекта
(`CONCEPT.md`, `DECISIONS.md`, `specs/`, `BOARD.md`/`BACKLOG.md`), а не
внешнее хранилище. Внешняя память лиду не запрещена, но это лишь
зеркало канона в файлах: сбросилась — ничего не потеряно, всё
восстановимо из проекта.

> **Подхват после `dreamteam update`.** Роли (субагент-Архитектор и
> импорт этой методики) подхватываются при **старте сессии** Claude
> Code, а не в момент апдейта. Если `update` запущен из активной
> сессии — перезапусти её, чтобы лид увидел новую роль.

## Лид

Основная сессия Claude Code в проекте (эта). Не отдельный артефакт, а
поведение по `CLAUDE.md`. Пишет прод-код, ведёт задачи, вызывает
Архитектора и Дизайнера и сводит их результаты. Живого трёхстороннего
чата между ролями нет: лид обращается к каждой роли отдельно и сам
объединяет ответы.

## Архитектор (read-only субагент)

Консультант по логике и архитектурным решениям. Живёт как субагент
`.claude/agents/architect.md`; Claude Code обнаруживает его
автоматически — отдельный импорт для него не нужен. Read-only
(Read/Glob/Grep): читает файлы методики, рассуждает, предлагает — но
сам не коммитит и не пишет код.

**Когда звать:** выбор подхода, разбор технического решения, ревью
архитектуры, сомнение «не выйдет ли боком». Не для написания кода (это
лид) и не для визуала (это Дизайнер).

**Как звать:** делегируй субагенту `architect` вопрос вместе с
контекстом — он сам дочитает нужные файлы методики. Например: «Спроси
Архитектора, стоит ли выносить X в отдельный модуль: дай контекст,
варианты с компромиссами и рекомендацию».

**Что возвращает:** разбор в форме контекст → варианты с компромиссами
→ рекомендация → открытая развилка, с пометкой, какие файлы методики
легли в основу. Когда решение созревает — предлагает готовую ADR-Lite
запись для `DECISIONS.md` в формате проекта.

**Петля «предложил → человек решил → ADR»:**

1. Архитектор предлагает решение и черновик ADR-записи.
2. Человек решает — Архитектор read-only и за него не решает.
3. Лид/человек вносит финальную запись в `DECISIONS.md`.

Так значимое решение оседает в файлах проекта, а не в летучей памяти
агента.

## Дизайнер (Claude Design через MCP)

Внешний агент Claude Design для визуальной работы: интерфейсы,
прототипы, визуальные спецификации. Лид вызывает его напрямую как MCP,
в субагент не оборачивает.

**Prerequisite — разовая настройка на уровне аккаунта:**

1. `claude mcp add --scope user --transport http claude-design https://api.anthropic.com/v1/design/mcp`
2. `/design-login` — OAuth-аутентификация (именно этот шаг подключает,
   не `add`).
3. (опц.) `claude mcp list` — проверить, что сервер зарегистрирован.

Доступ к Claude Design — на планах Pro / Max / Team / Enterprise
(beta). Если MCP не подключён или недоступен — это **не ошибка, а
развилка**: лид либо подключает Дизайнера, либо работает без него.
Дизайны используют design-system аккаунта (бренд-цвета, типографику),
если она настроена; для свежего личного проекта — дефолты Claude Design.

**Когда звать:** нужен визуальный дизайн или прототип интерфейса. Лид
передаёт Дизайнеру бриф из `specs/design-brief-template.md`, итерирует
и тянет результат в репозиторий как прототип.

**Важно:** Дизайнер выдаёт **веб** (HTML/CSS/JS), а не целевой стек
проекта. Его артефакт — визуальная спецификация; перевод в целевой
UI-стек всегда отдельный шаг лида.

## Честные ограничения

- Нет живого трёхстороннего диалога: Архитектор и Дизайнер —
  вызываемые роли, а не равные собеседники в общем чате.
- Субагент — консультация, а не стрим: виден результат, не
  промежуточные реплики.
- Архитектор реконструирует роль по промпту и файлам проекта; качество
  ответа = качество промпта + полнота файлов методики.
- Дизайнер мыслит вебом; перевод в целевой стек — шаг лида.
