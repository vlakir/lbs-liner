# Architecture Decisions

ADR-Lite: компактный лог архитектурных решений с обоснованиями.
Цель — через полгода можно ответить на вопрос «а почему мы тогда так
сделали?», не реконструируя контекст по коммитам.

## Формат

Каждое решение — короткий блок:

- **Дата** — когда принято.
- **Решение** — что решили (1 строка).
- **Контекст** — какая задача / ограничение к нему привели.
- **Альтернативы** — что рассматривали и почему отвергли.
- **Последствия** — что это нам теперь даёт и чего лишает.

Решения не редактируются после фиксации. Если решение пересмотрено —
добавляется новый блок со ссылкой на старый, старый помечается как
«Заменено решением от <дата>».

## Пример (удалить при заполнении шаблона)

### 2026-05-13 — SQLite вместо PostgreSQL для MVP

- **Контекст:** проект для одного пользователя, < 10 МБ данных, нужен
  быстрый запуск без отдельного сервиса.
- **Альтернативы:**
  - PostgreSQL — отвергли, нет резона держать отдельный процесс ради
    одного пользователя; миграцию делать всегда успеем.
  - JSON-файл — отвергли, теряем транзакционность и индексы.
- **Последствия:** деплой = один бинарь, бэкап = копия файла. При росте
  > 100 МБ или появлении конкурентного доступа — пересмотреть.

## Решения проекта

### 2026-08-30 — Выход собирается патчем входного CDR, а не генерацией с нуля

- **Контекст:** T001. CDR — закрытый формат; ни одна библиотека не умеет
  его писать (libcdr — только читать). Утилита обязана отдавать файл,
  который откроет CorelDRAW получателя.
- **Альтернативы:**
  - SVG/CMX на выход — отвергли: нужен именно .cdr, лишний
    шаг импорта у получателя.
  - Генерация CDR с нуля — отвергли: слишком много незнакомых
    обязательных структур; любая упущенная деталь ломает открытие.
  - Патч входного контейнера — выбрали: новые тела чанков дописываются
    в хвост data-файлов (ничего не сдвигается), перестраивается только
    дерево root.dat; служебные чанки клонируются от объектов-доноров.
    Совместимость с версией Corel отправителя достаётся бесплатно.
- **Последствия:** утилита работает только с CDR X7+ (zip-контейнер) —
  осознанное ограничение из CONCEPT.md; раскладка чанков (loda, trfd,
  outl, bbox) восстановлена по исходникам libcdr и закреплена юнит-
  тестами на реальной записи обводки. Проверку в настоящем CorelDRAW
  заменить нечем — она остаётся ручным шагом приёмки.

### 2026-08-30 — Смещения и стороны считает shapely, порядок подпутей — под две трактовки бита 0x08

- **Контекст:** T001. Параллельные линии на изломанной трассе с острыми
  углами и самопересечениями руками не построить надёжно; сторону
  «где красная» надо определять автоматически.
- **Альтернативы:**
  - Ручной офсет по нормалям — отвергли: острые углы и схлопывание
    колец дают самопересечения, это готовая функциональность GEOS.
  - Сторона по порядку обхода контура — отвергли: ненадёжно при
    смешанных направлениях; вместо этого голосование сэмпл-точек
    офсета против полигона зоны (точка-в-полигоне).
- **Последствия:** единственная тяжёлая зависимость — shapely (дружит с
  PyInstaller). В записи точек замкнутые кольца идут раньше открытой
  линии: бит 0x08 на moveTo Corel понимает как «этот подпуть замкнут»,
  а libcdr — как «закрыть предыдущий»; такой порядок корректен в обеих
  трактовках.
