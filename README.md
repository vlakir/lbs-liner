# lbs-liner

Служебная CLI-мелочь для оформительских задач в CorelDRAW: берёт
залитую цветом область в CDR-файле и заменяет её двойной контурной
линией (красная — со стороны бывшей заливки, синяя — с внешней).
Пригодится, когда границу зоны на плане или схеме нужно показать
линиями, а не заливкой. Читает и пишет CDR (zip-формат X7+, версии
17–22) самостоятельно, без установленного CorelDRAW и внешних
конвертеров.

## Использование

```bash
uv run python src/main.py                        # все .cdr текущей папки
uv run python src/main.py вход.cdr               # → вход-lines.cdr
uv run python src/main.py вход.cdr -o выход.cdr --red-width 3 --blue-width 2
```

Без аргументов обрабатываются все `.cdr` текущей папки, кроме уже
готовых `*-lines.cdr`; каждый файл получает соседа с постфиксом
`-lines`. Ошибка в одном файле не прерывает остальные.

- `--red-width` — толщина красной линии в пунктах (по умолчанию 3);
- `--blue-width` — толщина синей линии в пунктах (по умолчанию 2);
- `--gap` — просвет между краями линий в пунктах (по умолчанию 0 —
  линии вплотную, стык проходит по исходной трассе).

Что делает: находит залитый многоугольник зоны, мысленно снимает
искусственные замыкающие рёбра, отбрасывает черновики-дубли трассы, а
сами ломаные (основную линию, карманы, отдельные пятна) обводит парой
параллельных линий. Сторона для красной определяется геометрически — по
положению залитой области. Результат **добавляется новым слоем
«Двойная линия»**; исходное содержимое файла, включая заливку и другие
слои, не меняется вовсе — ненужное потом скрывается или удаляется в
самом Corel. Работает только со слоем, где лежит залитая зона; кривые
других слоёв не участвуют.

## Быстрый старт

Менеджер зависимостей и окружения: **`uv`** (выбран при
`dreamteam init`).

```bash
uv sync                       # поставить зависимости
uv run python src/main.py     # запустить
```

## Окно (GUI)

`lbs-liner-gui.exe` — то же самое мышкой: выбор файла (выход
подставляется сам), толщины и просвет, кнопка на один файл и на всю
папку, лог внизу. Консольный `lbs-liner.exe` остаётся для командной
строки и пакетного режима.

Локальный запуск окна: `PYTHONPATH=src uv run python src/gui_main.py`.

## Сборка исполняемого файла

Windows-exe собирает GitHub Actions (workflow `CI`, job `build-windows`):
на каждый merge в `main` артефакт `lbs-liner-windows` со свежими
`lbs-liner.exe` (CLI) и `lbs-liner-gui.exe` (окно). Скачать: страница Actions → прогон → Artifacts, либо
`gh run download --name lbs-liner-windows`. CI смоук-тестирует exe на
синтетическом образце (`examples/sample.cdr` — придуманная геометрия,
реальных данных в репозитории нет).

Локальная сборка (бинарь текущей ОС):

```bash
uv sync --group build
uv run pyinstaller lbs-liner.spec   # → dist/lbs-liner
```

## Проверки перед push

```bash
uv run ruff check .
uv run ruff format --check .
uv run mypy src tests
uv run pytest  # тяжёлый прогон — через scripts/pytest-guard.sh
```

Все четыре должны проходить с 0 ошибок. Обходные манёвры (`# noqa`,
`# type: ignore`, расширение `ignore`-секции) — только по согласованию.

## Структура проекта

- `src/` — корень исходников.
- `CONCEPT.md` — изначальное видение проекта (immutable).
- `DECISIONS.md` — архитектурные решения с обоснованиями (ADR-Lite).
- `BOARD.md` — рабочая Kanban-доска (To Do / Doing / Done).
- `BACKLOG.md` — парковка идей и побочных находок.
- `CHANGELOG.md` — журнал заметных изменений.
- `specs/` — спецификации крупных фич.
- `CLAUDE.md` — проектные правила для Claude (Claude Code).
